# Staff / Principal Data & AI Platform Engineer — Learning Roadmap

**Duration:** 18–24 months · **Effort:** 6–8 hours/week · **Primary outcome:** technical depth plus evidence of cross-team architectural influence.

This curriculum is tailored to an engineer with strong SQL/database experience and practical Azure, .NET, Spark, and data-platform exposure. It is **not** a beginner programming bootcamp. It addresses foundational gaps while developing skills for staff-level architecture and principal-level technical strategy.

## Design principles

- **Software engineering foundations first, using C#** because it is already familiar; transfer principles into Python and Scala.
- **Python is essential** for production data/AI engineering; learn packaging, typing, tests, performance, and PySpark, not just notebooks.
- **Scala is valuable but role-dependent**: learn JVM fundamentals and Scala for Spark internals and platform engineering; petabyte scale does not itself require Scala.
- **SQL remains a core differentiator**: expand into distributed SQL, query plans, cost-based optimization, and table formats.
- **Distributed systems and operations matter more than language syntax** at scale.
- **Staff/Principal is about influence**: architecture decisions, migration strategy, standards, mentoring, reliability, cost, and platform adoption.
- **Projects use synthetic/public data**, never proprietary work code or datasets.
- **Avoid paying for petabyte-scale infrastructure**: test on GB-scale synthetic datasets, demonstrate scaling principles and cost models.

## Starting this week

1. Score the baseline in `05-study-tracker.md`.
2. Select one modern C#/.NET engineering course, not several overlapping ones.
3. Create the repository template and begin the Job Management API.
4. Set a weekly 6–8-hour study block and a monthly review.

## Scope and reality check

A 24-month curriculum is an **educational plan**, not a guarantee of a Staff or Principal title. These levels require real-world evidence of multi-team impact. Use work opportunities, when appropriate, to practise design reviews, standards, mentoring, and measurable improvements; keep the portfolio independent.
